# turn-end-fix report

Branch: worktree-agent-a51448e3663da7257 (from issue-121-network-simple-flow at 23610aa). Fix commit: 541a2c9. Not pushed, no PR.

- Bug: the end frame went out on a 1 s `is_processing` idle debounce, so a gap between the terminal tool result and the next model call ended the turn before the hub_msg answer (shell: "finished without a reply").
- Signal: new `QueueProcessor.note_chain_end()` (packages/kollabor-agent/.../queue_processor.py), called from the `finally` of `_drain_queue` and of `_hub_continue` (kollabor/llm/message_handler.py). It reports only when `turn_completed` (or cancel/error), `processing_queue` is empty and `_turn_lock` is free, then calls `HubPlugin.network_chain_ended(failed=bool(last_turn_error))`. No event bus type was added; it reuses the `hub_plugin` service lookup `_bridge_relay` already uses.
- Hub side (plugins/hub/plugin.py): `_NetworkTurn` gets `ended`/`failed`; the idle debounce, `idle_since` and `_NET_TURN_SETTLE_SECONDS` are gone. The relay tick (`settle_network_turn`) sends the plain-text forward then the end frame once `ended`. Chain ends before the model ran for the request, or from the chain that was busy when it arrived, are ignored. Ack/no-model requests still end at once; the 600 s drop stays.
