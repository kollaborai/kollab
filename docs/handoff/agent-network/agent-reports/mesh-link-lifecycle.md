# Mesh peer-link lifecycle fix (refs #121)

- Branch `worktree-agent-af836e1af0e26d0b5`, code commit `1b4ccf8` on top of `3d49076`; this note is the commit after it.
- Fix in `plugins/hub/peer_transport.py` and `secure_conversation.py`: only the lower peer id proposes; the link names its outbound session and the responder checks the session the proposal arrived on; an unchanged link is not re-proposed, renewal past half life is a fresh `issued_at` and a higher revision (per-edge proposed counter, so a lost reply never reuses one); every link check is "is its session still open" (`_link_is_live`) instead of the min id.
- `_accept_gossip` and the forward import skip a record or link older than the one held instead of aborting the exchange (`_holds_newer`, `_holds_newer_record`).
- Second root cause the new test found: a transit hop rebuilt the outgoing frame from its own router, so its trace named link ids the destination's frame lacked after a renewal. It now forwards the links it was handed.
- `request()` falls back to the relay once when the mesh route fails for a peer that is also on the relay.
- Regression test: `test_mesh_network.py::test_links_between_members_stay_valid_across_thirty_concurrent_refreshes` (A-B-C, 30 rounds x 15 s, concurrent refresh, same link per pair each round, A->B->C and B->C calls). Failed on the old code (invalid lifetime, ingress session is stale, peer route delivery failed); passes now. Also added `test_links_recover_when_a_member_drops_its_secure_sessions` and `test_a_failed_mesh_route_to_a_peer_on_the_relay_falls_back_to_the_relay_once`.
- Tests changed, assumption no longer true: `mesh_network` fixture warm-up (the lower id starts each pair's exchange; ids are random per run); `test_link_refresh_reuses_statement_until_half_life` (unchanged link returns no proposal, renewal asserts a higher revision and fresh `issued_at`); `test_a_link_proposal_is_made_only_after_the_outbound_session_is_open` (spies on the lower-id node).
- Results: the 4 named tests and `test_relay_peer_with_mesh_link_keeps_native_relay_path` pass; touched mesh tests 8/8 in 5 consecutive runs; full suite 5287 passed, 9 skipped, 0 failed; ruff clean; both CHANGELOGs `cmp` identical.
- Not done: no live run, no rebuild (dev4 needs one), m1/m3 proofs not rerun. Residual: when the proposer drops its outbound session after a failed request, the responder counts the link live for up to one 15 s tick (the relay fallback covers relay peers); a proposer restart right after an unacknowledged accepted proposal can reuse a revision until that link expires (5 min at most).
