### Fix brief: unfinished web activation recovery
- Symptom/reproduction: a tab frozen or closed while a plugin's activation function is running is retried on reload instead of skipped, even though its boot never finished.
- Root cause: `PluginHost` cleared the session freeze marker as soon as the module import finished, before `PluginLoader` awaited its activation function.
- Fix layer: keep the marker through activation and clear it only on the current attempt's successful commit, failure, or removal. The loader already ignores stale attempts.
- Regression: `freeze-marker-red.log` shows the new unfinished-activation/reload test failing before the fix; `freeze-marker-green.log` shows all 29 host and loader tests passing, including stale-import and retry cases.
- Siblings/risk: import failure, timeout, cancellation and replacement share existing guarded loader cleanup. A page closed during a pending asynchronous activation is intentionally skipped on reload under the existing unfinished-boot contract. The marker also remains present during registry publication and is cleared only if the same resource still owns the load; `freeze-publish-test.log` covers publication and the host/loader lifecycle. Full frontend and live gates remain required at the final SHA.

### Fix brief: installed and development Settings values
- Symptom/reproduction: changing an installed or development plugin setting and clicking Save Settings sent the panel's namespaced `plugin-values.<id>.<key>` path to the plugin settings endpoint, which validates only the manifest's local `<key>` and rejected the request.
