- Scheduled hub cron jobs are readable outside the terminal: each
  agent's unix socket answers a read-only, local-operator-only
  `cron_jobs` question, the engine aggregates the schedules across
  live agents, and the web UI Settings gains a read-only
  Cron Jobs tab listing every live agent's schedules, next fires,
  and per-agent errors (issue #612).
- Schedules now persist and fire without drift: they are stored in
  `~/.kollab/schedules.json` and survive restarts, the hub coordinator
  sleeps until each schedule's next fixed grid time instead of polling,
  every fire is recorded in `~/.kollab/schedules-runs.jsonl` as the Last
  run, and a device that was offline fires one catch-up run on return and
  then continues on its normal times (issue #612, stage 1 of the approved
  build order).
