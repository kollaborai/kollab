- Scheduled hub cron jobs are readable outside the terminal: each
  agent's unix socket answers a read-only, local-operator-only
  `cron_jobs` question, the engine aggregates the schedules across
  live agents, and the web UI Settings gains a read-only
  Cron Jobs tab listing every live agent's schedules, next fires,
  and per-agent errors (issue #612).
- Schedules now persist and fire without drift: they are stored in
  `~/.kollab/schedules.json` and survive restarts, the hub coordinator
  sleeps until each schedule's next fixed grid time instead of polling,
  every fire is recorded in `~/.kollab/schedules-runs.jsonl` as the Last
  run, and a device that was offline fires one catch-up run on return and
  then continues on its normal times (issue #612, stage 1 of the approved
  build order).
- A schedule now reaches its agent instead of only sending a message: an
  agent that is not running is started detached with the fire's prompt as
  its first message, a busy agent either gets the prompt queued behind its
  current turn or a second one-run instance of the same identity runs it
  (per the schedule's busy choice, and that instance exits when the run is
  done), and an idle agent gets the prompt directly. Every fire carries the
  schedule id so replies and run records line up (issue #612, stage 2).
- Schedules reach every device on the network: schedules.json travels with
  the sealed config sync as its own bundle, a change on the primary is
  pushed to every joined device, and an edit made on a secondary device is
  sent to the primary as a signed change request that it applies and pushes
  back out. Wherever the file changes, the schedule timer wakes and
  recomputes its next due time at once (issue #612, stage 3).
